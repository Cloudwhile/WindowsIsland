# 发布兼容性与迁移

## 合约与宿主版本

`contractVersion` 表示合约大版本，当前为 `1`；Contracts 的 `AssemblyVersion` 固定为 `1.0.0.0`。包版本、程序集 ABI 和宿主版本各有用途。同一合约大版本不新增必填接口方法；新行为使用可选接口或 `GetService<T>()`，插件必须处理服务为 `null`。

清单可设置 `minimumHostVersion`，使用严格 SemVer，例如 `0.1.0`，不带 `v`。宿主启动前拒绝最低版本不满足的插件。针对准备部署的宿主执行：

```powershell
wini-plugin doctor C:\expanded-plugin --host-version 0.1.0
```

未提供 `--host-version` 时，仅完成包与合约检查，并提示尚未核验目标宿主版本。工具不会推断其他应用的版本。新插件应随与目标宿主相同构建的 SDK 开发，并在该宿主实际导入验收。

## 更新与重新授权

每次成功覆盖（包括相同版本和相同字节）生成新安装代次，插件默认关闭，重新启用需要确认。旧上下文、网络请求、设置变更及控件回调失效。安装失败回滚恢复原包、原代次、来源凭据和原授权。

不要在运行期间直接改写安装目录；运行会话持有只读文件句柄。通过新 ZIP 更新并让宿主完成停用和替换。即使大小及修改时间保持相同，包变化也不能复用旧授权。

## 设置迁移

- 字符串和布尔键保持兼容；整数、枚举、URL 通过原字符串 API 读写。
- 静态版本 1 不自动变成版本 2。使用扩展字段时显式更新 `schemaVersion`。
- 必填项在初始化前校验。用户先在关闭状态填写，再启用。
- 普通字符串改为秘密字段时，宿主首次打开该插件的设置存储便用 DPAPI 加密旧值并替换磁盘明文。秘密使用独立的类型信封保存，普通字符串不会仅因前缀相同被当成新格式密文。
- 可解密的旧格式密文会迁移到类型信封。旧格式没有类型标记：形似旧密文却无法验证的值会加密隔离，需重新填写；不会将其当作有效密码继续使用。新格式的损坏密文同样需要重新填写。
- 更新和卸载保留同标识的设置及数据；业务迁移可读取 `PreviousVersion`，迁移应可重复并保留回滚所需数据。

从未启用的外部插件不会为设置查看或卸载而执行 DLL。首次初始化必须能处理 `PreviousVersion == null`。

## 发布前验证

执行 `validate`、`test`、`pack`，再对解压结果执行带目标版本的 `doctor`。检查 ZIP 摘要，在目标宿主导入、配置、启用并显示首条通知，验证立即停止及重新启用。模拟网络通过不代表实际服务已连通；公开分发前按实际服务核对披露和目的地。
