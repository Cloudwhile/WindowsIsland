# 常见问题与反馈

## 显示“系统通知尚未就绪”

1. 在 **初始化** 页查看应用初始化和通知访问是否完成。
2. 按提示完成初始化，授权后等待应用重启。
3. 如果通知访问未允许，通过对应图标或 Windows 设置入口授权，再刷新状态。

这项提示仅针对系统通知。已连接的微信等独立来源与通知预览仍可使用，不必为了测试预览反复初始化。

## 能预览，但没有收到消息

1. 在 **消息来源** 页确认所需来源已开启且已连接。
2. 微信、Telegram 先确认桌面客户端已运行并登录。
3. 检查游戏与全屏静音是否正在生效。
4. 使用一条新的消息验证，启动前的历史消息不会重放。
5. 通过系统通知接收时，检查目标应用是否实际发出了 Windows 通知。

如果只是某个来源失败，先处理该行的说明或重试，不必停用其他来源。

## 微信连接失败或没有头像

确认客户端已登录，按消息岛提示检查微信辅助访问，再点击重试。客户端版本变化可能影响直连兼容性。

头像只在客户端提供且能够读取时显示，缺失时可能显示应用图标。系统通知可作为另一种接收途径，但必须单独完成初始化、授权，并由微信发出系统通知。

## Telegram 显示未运行

先打开并登录 Telegram 桌面版，再刷新来源状态。仍然失败时记录 Telegram 和消息岛版本，生成诊断报告后反馈。

## 通知重复、提前消失或没有补弹

新消息可以替换旧消息，并重新计算约五秒的显示时间。头像等元数据补全不会延长时间；关闭当前消息后仍继续监听。

游戏或全屏静音期间收到的消息不会在静音结束后补弹。多个来源的去重依赖可用的事件身份，反馈重复问题时请说明开启了哪些来源，避免公开消息正文。

## 毛玻璃看起来没有变化

检查外观页的毛玻璃和背景透明度，再查看 Windows 透明效果及高对比度设置。可在通知后方放置有文字的窗口，预览背景效果。

## 下载或更新失败

确认网络可以访问 GitHub 发布附件。取消后可重试，应用内下载支持继续已有进度。校验失败时重新下载，不继续运行不匹配的文件。

自动更新不可用时，从[下载页](../download/index.md)获取安装器并手动覆盖安装。详细步骤见[更新与预发布](../download/update.md)。

## 插件导入失败

检查是否选择插件 ZIP，而非应用便携包；确认该插件支持当前消息岛版本。包的清单、入口、依赖或标识不正确时，需要开发者重新打包。

开发者可对照[清单与标识](../plugins/manifest.md)和[打包指南](../plugins/packaging.md)排查。

## 生成诊断报告

1. 打开 **诊断与反馈** 页。
2. 查看最近记录，展开与问题有关的条目。
3. 点击生成图标，先预览报告。
4. 点击复制图标复制报告 JSON，或使用导出图标保存文件。
5. 通过反馈图标打开 [GitHub Issue 表单](https://github.com/Cloudwhile/WindowsIsland/issues/new/choose)，自行填写并选择是否附加报告。

报告不会自动上传，不包含消息正文、头像或账号信息。Issue 是公开内容，提交前请检查文字、截图与附件。

本机记录保留最长七天，重复问题可能合并为累计次数。关闭采集后已有记录仍可查看和导出；清除只移除应用中保存的记录，不删除此前导出的文件。

反馈时建议提供消息岛完整版本、Windows 版本、安装或便携方式、出现问题的来源、复现步骤和预期结果。截图中遮盖私人会话与个人信息。
